# CLAUDE.md

This file provides guidance to Claude Code (claude.ai/code) when working with code in this repository.

## What this repo is

The live NixOS system configuration for a single host, `helios` — an Acer Predator
Helios 300 laptop (Intel i7-7700HQ, Intel HD Graphics 630 iGPU + NVIDIA GeForce
GTX 1060 Mobile, user `pep`). The repo *is* `/etc/nixos`, so edits here change the
system on the next rebuild — there is no separate deploy step or target directory.

The structure is deliberately kept in sync with the `maggie` config (the AMD
desktop). Same module layout, same conventions, same scripts — the differences
are hardware and what's installed. Keep it that way: if you change the shape of
something here, it should be a change you'd also want on maggie.

This is a **channel-based** config, not a flake. There is no `flake.nix`;
`nix.settings.experimental-features` only enables the CLI, it doesn't make the
system flake-managed.

## Commands

```bash
scripts/nurse.sh          # nixos-rebuild switch          -- apply config as-is
scripts/nurse-update.sh   # nixos-rebuild switch --upgrade -- bump channels, then apply
nixos-rebuild dry-build   # evaluate + show what would build, change nothing
nixos-rebuild test        # activate without adding a bootloader entry (reverts on reboot)
nixos-rebuild switch --rollback   # undo the last generation
```

Run these as root from `/etc/nixos`. `dry-build` is the cheap way to catch eval
errors (typos, missing attrs, bad option names) before touching the running system.

## Structure and conventions

`configuration.nix` is only an import list plus GC/optimise settings and
`system.stateVersion`. All real configuration lives in `import-NN-<topic>.nix`
files, each a standalone `{ config, pkgs, ... }:` module.

- **A new module file must be added to the `imports` list in `configuration.nix`**
  or it is silently ignored.
- The `NN` prefix is ordering-for-humans only; NixOS module evaluation is
  order-independent.
- `environment.systemPackages` is declared in *several* modules (network,
  desktop, packages) and NixOS merges the lists. Put a package next to the
  feature it belongs to rather than centralizing everything in
  `import-06-packages.nix`. The same merge applies to `users.users.pep.extraGroups`,
  set in both `import-01-user.nix` and `import-08-gpu.nix`.
- `hardware-configuration.nix` is generated by `nixos-generate-config` — don't
  hand-edit it, **except** for the `rust1tb` mount block, which is added by hand
  and must be re-added if the file is regenerated.

Module map: `00` bootloader/zen kernel · `01` user `pep` · `02` networking +
tailscale · `03` locale (es_ES, Europe/Madrid) · `04` pipewire · `05` GNOME/GDM ·
`05` Hyprland · `06` packages, programs, AppImage/nix-ld · `07`
docker/steam/ssh/sunshine/printing · `08` Intel+NVIDIA graphics.

## How this host differs from maggie

- **`import-08-gpu.nix`** is the big one. Maggie is AMD + ROCm; this is Intel
  iGPU + NVIDIA PRIME. See the NVIDIA notes below.
- **No `<unstable>` channel.** Maggie pulls `quickshell`, `flutter`, `gemini-cli`,
  `android-studio`, `android-tools` from `<unstable>`. This host is on the 26.05
  channel where all of those are in stable, so the `let` bindings are commented
  out in `import-05-desktop-hyprland.nix` and `import-06-packages.nix` rather
  than deleted. `scripts/add-channel-unstable.sh` brings the channel back if a
  future package needs it.
- **Dev toolchains are commented out**, not installed: android-tools,
  android-studio, android-studio-tools, flutter, gemini-cli, claude-code. This
  is a secondary machine. `git`, `vscode` and `ffmpeg` are still installed.
  Because flutter is out, `programs.fish.shellInit` (which exported
  `FLUTTER_SDK` on maggie) is commented out too.
- **`adbusers`** is commented out of `users.users.pep.extraGroups`, since that
  group only exists when `programs.adb.enable` is on and android dev is off here.
- **`system.stateVersion` is `26.05`**, not maggie's `25.05` — this machine was
  reinstalled on 26.05.

## NVIDIA on this machine

- The GTX 1060 is **Pascal** (GP106). NVIDIA dropped Maxwell/Pascal/Volta after
  the **580** branch, so `hardware.nvidia.package` is pinned to
  `nvidiaPackages.legacy_580`. The channel default (`stable`/`production`, 595.x)
  will *not* drive this card. Don't "modernize" that pin.
- PRIME is in **offload** mode: the Intel iGPU drives the display and the 1060
  spins up on demand. Run GPU-hungry things with `nvidia-offload <cmd>`. For
  flatpaks, set `__NV_PRIME_RENDER_OFFLOAD=1` and
  `__GLX_VENDOR_LIBRARY_NAME=nvidia` via flatseal.
- `sync.enable` is the alternative (NVIDIA drives everything, worse battery).
  It's left commented in the same block — never enable both.
- `modesetting.enable = true` is required for the Wayland sessions (both GNOME
  and Hyprland), not optional.

## Things that will bite you

- **Never change `system.stateVersion`.** It is pinned to the original install
  and is not a version to keep current; upgrades happen by moving the `nixos`
  channel, not this value.
- **UUIDs in `hardware-configuration.nix` change on reinstall.** The `rust1tb`
  disk (`/dev/sdb`) kept its UUID across the last reinstall, but root/boot/swap
  did not.
- `programs.appimage.package` in `import-06-packages.nix` carries a non-obvious
  override: it re-wraps `buildFHSEnv` to export `GST_PLUGIN_PATH_1_0` because
  some AppImages clear `GST_PLUGIN_SYSTEM_PATH_1_0`. The inline comment explains
  why — keep it if you touch that block.
- `programs.nix-ld` exists so precompiled binaries (VS Code extensions shipping
  their own binaries) can run. Missing-shared-library errors from such binaries
  are fixed by adding to `programs.nix-ld.libraries`, not by patching the binary.
- The user's shell is `fish`.
- Packages are commented out rather than deleted when dropped — this is the
  existing style for things that may come back.
- Hyprland/Quickshell dotfiles under `hypr-quickshell-config/` are **not**
  installed by this repo. There's no home-manager wired in. Copy them into
  `~/.config` by hand (`hypr-quickshell-config/copyconfig.sh`).
